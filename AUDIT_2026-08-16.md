The envelope is advanced in all four render paths (prepared / Bungee / warp / unity), not just some. Undo coalescing on the ADSR knobs is correct.

The problems below are mostly at the edges.

## P0 — Address before anything else

### 1. The git repository is 3.9 GB for 134 tracked files
`.git/objects/pack` = 3.71 GiB, plus 174 MB of orphaned garbage from an interrupted repack (`.git/objects/pack/tmp_pack_vlSgZk`).

Six blobs of ~614 MB each remain in history (almost certainly old `.pkg` installers or htdemucs model exports). Two abandoned branches — `codex/cleanup-large-release-history` and `codex/backup-before-large-file-cleanup` — show this was attempted and never finished.

GitHub Desktop will be slow or will fail outright on clone/push. Also `tools/gh` (37 MB, the GitHub CLI binary) is tracked and should not be.

Needs `git filter-repo` + force-push, coordinated so you don't lose the local branches.

### 2. "Chop at transients" was silently deleted
`chopAtTransients()` (`PluginProcessor.cpp:6393`) and `TransientSensitivity` (`PluginProcessor.h:348`) now have **zero callers anywhere in the codebase**. The `CHOP @ TRANS.` button and its sensitivity popup (Light / Medium / Fine) were replaced *in place* by `CHOP MANUALLY` rather than added next to it.

If dropping transient chopping wasn't a deliberate product decision, this is a shipped-feature regression. Both buttons can coexist — there's layout room in the transport row.

### 3. `CHOP MANUALLY` destroys all chops on one click, no confirmation
`PluginEditor.cpp:~5430` → `processor.clearAllChops()` fires the instant the toggle goes on. It is undoable (a snapshot is pushed), but there's no prompt, and the button is a `SmoothHoverButton` with `cueStyle = "flatAction"` — and the `flatAction` painter ignores `getToggleState()` entirely (`PluginEditor.cpp:1216`), so **the button never lights up to show the mode is active**. A user can click it, lose their chops, and not see that anything is on except the waveform hint bar.

## P1 — Correctness / audio risk

### 4. Gate voices lost their fade safety net
`PluginProcessor.cpp:3454` — note-off now calls `beginEnvelopeRelease()` *instead of* `startFade()`. Voice lifetime now ends **only** via:

```cpp
if (v.envelopeConfigured && v.envelopeReleaseTriggered && ! v.envelope.isActive())
    v.playbackActive = false;                      // line ~3306
```

The envelope only advances when a render path emits output samples. If any block produces zero frames — Bungee priming stall, warp cache miss, prepared-cache swap mid-note — the envelope stalls and the voice never releases. **Stuck note.** Keep a belt-and-braces fade or a wall-clock timeout as a backstop.

### 5. Non-MIDI playback gets an envelope that never releases
`renderVoiceSegment` starts an envelope for the live path (`v.startEnvelope(*activeChop, ...)`, ~line 2870), but `autoRelease` requires `v.playbackTriggeredByMidi && v.midiOneShot`. So mouse-preview and transport playback of a chop with `sustainLevel < 1.0` play **quieter than the same chop triggered over MIDI**, and never apply release. Auditioning no longer matches playback.

### 6. Long release swallows short chops
`releaseMilliseconds` ranges to 4000 ms. Auto-release fires when `outputSamplesUntilStop <= releaseSeconds * sampleRate`. Any chop shorter than the release time starts its release on frame 0 — the chop becomes nothing but a fade-out. No clamp against chop length.

### 7. Mixed manual/auto chops break the positional MIDI map
`handleMidiEvent` falls back to `chopIdx = note − effectiveRoot` indexing into `chops[]`, but only accepts the hit if that chop's `assignedMidiNote == -1`. Manual chops are inserted **sorted by `startSample`**, so adding one shifts the array index of every legacy chop after it — silently remapping or dead-ending their notes. There's no user-visible model for which pad plays what once the two systems are mixed.

### 8. MIDI note lookup is now O(n) on the audio thread
`PluginProcessor.cpp:~3492` — every note-on linearly scans all chops for `assignedMidiNote`, then does a second positional lookup. Fine at 16 chops, measurable at hundreds. A note→chopId index rebuilt on each `chopState` swap would make this O(1).

### 9. MIDI is dropped when `samplesToProcess == 0`
The dispatch loop is `while (currentOffset < samplesToProcess)`. On a zero-length block the body never runs, `midiIterator` never advances, and **every event in that block is discarded**. Mid-capture that means a lost note-off: the capture stays armed with a phantom held note. Rare (most hosts don't do this) but cheap to guard.

## P2 — Should fix, not urgent

### 10. `getMidiMappingText()` has always been wrong
`PluginEditor.cpp:6072` advertises `root = chop 1, root+2 = chop 2` — two semitones per chop. `getMidiNoteForChopId()` returns `getMidiRootNote() + i` — **one** semitone per chop. Pre-existing bug, not from this change set, but now more visible.

### 11. `setChopEnvelopeParameter` deep-copies all chop state per knob tick
Full `ChopState` copy — every chop, every `warpMarkers` vector — on each slider callback. It matches the existing `setSelectedChopGain/Pitch` pattern, so it's consistent rather than novel, but it's now the heaviest instance (4 knobs, continuous drag).

### 12. `addManualChop` dereferences `chopState` without a null check
`*std::atomic_load (&chopState)` — every sibling mutator (`clearAllChops`, `setChopEnvelopeParameter`) checks first. `chopState` is initialized in the constructor and never stored null, so this is latent, not live. Worth making consistent.

### 13. State `version` is write-only
Bumped 4 → 5 in `getStateInformation`, but **nothing anywhere reads it**. No migration branch exists. The new fields all have safe defaults so v4 projects load correctly — but the version field is giving false confidence that a migration path exists.

### 14. Plugin version still says 1.0.7
`CMakeLists.txt:9` — `project(CueSampler VERSION 1.0.7)`, matching the last release commit, while two significant features and a state-format bump sit uncommitted.

### 15. Manual mode is editor-local and evaporates on window close
`~WaveformDisplayComponent` force-calls `setManualChopModeActive(false)`. Closing the plugin window mid-chop silently exits the mode and cancels a pending capture. Related: `buildChopsFromAnalysis` correctly early-returns while manual mode is active — but if the window closed first, a late analysis result **will** repopulate the chop list the user just cleared.

## Structural — the thing actually slowing you down

### 16. Two files are 60% of the codebase
```
PluginEditor.cpp      7,211 lines   312 KB
PluginProcessor.cpp   6,870 lines   284 KB
PluginProcessor.h       802 lines
```
Every UI class — `ChopAdsrMenu`, `WaveformDisplayComponent`, `TransportSection`, the LookAndFeel, all of it — is defined inline in a single translation unit. A one-line tweak to a button label recompiles the largest TU in the project. In CLion this is the dominant cost of every iteration.

Splitting `WaveformDisplayComponent` and the LookAndFeel into their own files would be the highest-leverage refactor available, and is low-risk (pure code movement).

### 17. No automated tests
`test_stem_separator` is wired into CMake but is `EXCLUDE_FROM_ALL` and is a manual CLI tool, not a test. There's no `enable_testing()` / `add_test()` anywhere. `MANUAL_TEST.md` is the entire QA strategy — and this change set added **20+ new manual checklist items**, several of which (envelope timing across 6 playback modes × 4 buffer sizes) are combinatorially impractical to check by hand.

The chop-state mutators and the envelope math are pure functions of their inputs and would be straightforward to unit-test headlessly.
